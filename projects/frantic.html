FRANTIC — Hybrid Identity and Business Portals

Academic group capstone · Fanshawe College · INFO-5137
Mikel Omeibe, Josiah Nimfa and Nicholas Tulang

Project overview

A lab for a fictional organization connecting on-premises Active Directory to Microsoft Entra ID. A SharePoint intranet and IT, HR and Collaboration portals demonstrate centralized authentication with departmental permissions.

Infrastructure and applications

Hyper-V hosts DC1 for AD DS and DNS, DC2 for Entra Connect Sync, SharePoint Server 2019, SQL Server, and WEBAPP01 for IIS and ASP.NET Core applications. The IT and HR portals use OpenID Connect. SharePoint uses a trusted Entra identity provider. LDAP supplies HR directory information and SharePoint REST APIs support list integration.

The IT Portal provides a ticket entry point. The HR Portal displays employee accounts and SharePoint leave requests with HR.Access and Manager.Access roles. The Collaboration Portal provides departmental navigation, while document workspaces, team spaces and activity tracking remain marked coming soon.

My contribution

My primary work focused on the HR Operations Portal, including ASP.NET Core configuration, IIS deployment, Entra authentication, HR and manager role checks, LDAP directory integration, SharePoint REST integration, troubleshooting and demonstration documentation. The wider infrastructure and other portals were developed collaboratively.

Deployment troubleshooting

A generated HRPortal.styles.css file had been copied into wwwroot and conflicted with compilation output. I investigated the static assets, removed the duplicate in an isolated build copy and verified a successful publish.

Validation and remaining work

Screenshots show synchronized accounts, role definitions, successful application sign-ins, HTTPS bindings and matching pending leave-request data. A persisted approval in both systems, authorized and denied role tests, detailed Conditional Access evaluation and a continuous SSO walkthrough would strengthen the validation. The enabled policy list alone does not establish MFA enforcement. Directory attributes are partly unpopulated and duplicate DNS records need review.
